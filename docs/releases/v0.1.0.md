# AskMe v0.1.0 — experimental research preview

**Draft release notes, 2026-09-08.** No release tag is asserted by this document.
Candidate baseline: [`2293d49`](https://github.com/den-run-ai/askme/commit/2293d49ab984b1575ef88c7b9b00b1d40e2d1fcc).

AskMe is a minimal Python harness for studying whether small local LLMs can
complete bounded coding workflows. It also supports hosted models through
OpenRouter. This is a **source-only** research preview: clone the repository
and follow the [Quick Start](../../README.md#quick-start), using Python 3.10+
and uv 0.12.1. It is **not a sandbox**; model-generated shell commands run
with the launching user's permissions.

The evidence supports useful bounded coding examples and exposes gaps between
producing a correct artifact, testing it, and terminating successfully.
Reliability on realistic feature work remains open. These records do not
establish a causal harness benefit, a model-size effect, or general readiness
for autonomous software development. The affected historical 9/9 C-repair
result is omitted from the announcement.

## What changed

- Fresh task attempts can execute verification commands used by earlier
  attempts. Repetition guards still stop loops within an attempt. Accepted
  `done` and `fail` claims now have explicit control receipts, separate from
  executed actions and independent acceptance.
- The FeatureBench adapter copies and verifies both pinned runtime modules;
  current modular revisions can launch in a clean evaluation container.
- Timed-out shell actions terminate their owned POSIX process groups with
  bounded cleanup. Benchmark records preserve measured trial time separately
  from the configured timeout.
- CI watches `actions.py`, includes macOS tests and a local-server contract
  lane, and keeps paid OpenRouter PR runs opt-in. The web evaluation workflow
  follows the current model/configuration contract.
- Public documentation corrects the native-tool interface, planner visibility,
  completion semantics, and the limits of historical comparisons. See the
  [talk material](../../talks/berkeley-agentic-ai-summit-2026/README.md).

## Known limits

Completion remains distinct from test acceptance. Live truncated tool arguments
are rejected rather than salvaged. Whole-run cooperative cancellation and
aggregate resource limits remain open; descendants that create separate process
groups can outlive an outer timeout. Local memory, server build, quantization,
context, and reasoning settings materially constrain execution. See
[SECURITY.md](../SECURITY.md), [configuration](../configuration.md), and
[the release tracker](https://github.com/den-run-ai/askme/issues/85).
