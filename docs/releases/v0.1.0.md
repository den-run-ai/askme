# AskMe v0.1.0 — experimental research preview

**Release notes prepared 2026-09-08; tag/publication pending.**
Evaluated runtime: [`6a212cf`](https://github.com/den-run-ai/askme/commit/6a212cf711afe7a327fecf4b7f4d7bf866e11d16),
byte-identical to the earlier evaluated `28534c6` runtime.
The serving/slide publication change (#110) adds evaluation safeguards and
evidence without changing those runtime bytes. The separate module extraction
(#81) changes the source layout and preserves frozen evaluation snapshots;
its offline parity tests are not a new live evaluation of the refactored code.

AskMe is a minimal Python harness for studying whether small local LLMs can
complete bounded coding workflows. It also supports hosted models through
OpenRouter. This is a **source-only** research preview: clone the repository
and follow the [Quick Start](../../README.md#quick-start), using Python 3.10+
and uv 0.12.1. It is **not a sandbox**; model-generated shell commands run
with the launching user's permissions.

The evidence supports useful bounded coding examples and exposes gaps between
producing a correct artifact, testing it, and terminating successfully.
Reliability on realistic feature work remains open. These records do not
establish a causal harness benefit, a model-size effect, or general readiness
for autonomous software development. The affected historical 9/9 C-repair
result is omitted from the announcement.

The [historical local E4B pilot](../../talks/berkeley-agentic-ai-summit-2026/evals/local-repair-evidence.json)
provides a narrow positive: four accepted repairs of one seeded health-check
bug, with all four shipped-profile agents exhausted. The original pilot's two
strict passes used a larger diagnostic budget. Small accepted repairs exist;
dependable autonomy and net time savings are not established. This is separate
from the newer serving-only probes and hosted real-repository attempt below.

## What changed

- Fresh task attempts can execute verification commands used by earlier
  attempts. Repetition guards still stop loops within an attempt. Accepted
  `done` and `fail` claims now have explicit control receipts, separate from
  executed actions and independent acceptance.
- The FeatureBench adapter copies and verifies the complete pinned runtime;
  current modular revisions can launch in a clean evaluation container.
- Timed-out shell actions terminate their owned POSIX process groups with
  bounded cleanup. Benchmark records preserve measured trial time separately
  from the configured timeout.
- CI watches every runtime module, includes macOS tests and a local-server contract
  lane, and keeps paid OpenRouter PR runs opt-in. The web evaluation workflow
  follows the current model/configuration contract.
- Public documentation corrects the native-tool interface, planner visibility,
  completion semantics, and the limits of historical comparisons. See the
  [talk material](../../talks/berkeley-agentic-ai-summit-2026/README.md).
- New evaluation adapters qualify representative serving latency, actual
  planner/native-tool contracts and cancellation recovery before a task. Hosted
  trials pin their route and reserve bounded API spending before every request.
  Original negative trials and subsequent reporting corrections remain separate.
- Two controller tests now script their missing task-local replan responses.
  A fail-closed Requests guard prevents ordinary tests from silently using an
  available model server. The [observed test-isolation incident](../../tests/bench_records/2026-09-08-offline-test-isolation/README.md)
  is retained; earlier passing counts are not proof that those runs were hermetic.
- The separately reviewed physical module extraction keeps the source-only
  `python3 askme.py` entry point and compatibility API. Provider calls, policies
  and controller sequencing have distinct owners; no dependency, prompt budget,
  acceptance rule or model-capability claim is added. Evaluation launchers pin
  the full module inventory instead of borrowing files from another checkout.

## Recorded validation and external outcome

The [guarded local handoff](2026-09-08-hermetic-validation.json) passed
1,421 tests. The subsequent [model-identity review fix](../../tests/bench_records/2026-09-08-serving-qualification/offline-model-identity-audit.json)
passed 1,432 tests with 30 expected live-test skips and 96.46% branch-aware
coverage; Ruff, formatting and type checks passed. The already-running E4B
server log was unchanged before/after each guarded suite. These dated records
supersede the hermeticity claim for the earlier 1,415-pass run, whose
missing-mock incident is retained above.

Linux CI and both native macOS Python suites passed; the repaired runtime
also passed its local-server contract ([run](https://github.com/den-run-ai/askme/actions/runs/34174642414)).
The final evaluation setup passed [Linux CI](https://github.com/den-run-ai/askme/actions/runs/34175780682)
and [macOS CI](https://github.com/den-run-ai/askme/actions/runs/34175780679).

The single predeclared Qwen3-4B attempt on a real Requests bug **did not resolve**.
It timed out after 720.235 seconds during planning, before any coding action
or completed HTTP response. The patch is empty and independent acceptance
still reproduces the original bug. Baseline/no-op controls fail; gold passes
21 checks. All outcomes and the [complete evidence](../../tests/bench_records/2026-09-08-requests-qwen4b-macos/README.md)
are retained with no selective rerun. Token consumption is unknown because no
usage returned; hosted API charge was $0.

This is a serving/deadline failure on a 7 GiB virtual Mac, not evidence that
the 4B model cannot solve the task. A virtual Metal device was detected, but
physical 16 GB reference-Mac performance was not reproduced. The result
adds no reliability estimate, model-size effect, or causal harness benefit.

The [physical M1 follow-up](../../tests/bench_records/2026-09-08-serving-qualification/README.md)
confirmed Qwen's full 37/37 GPU-layer offload but found slow larger requests
and delayed queued cancellation in both Qwen and Gemma E4B. Both failed the
frozen serving gate, so no local coding task ran. Battery Low Power Mode was
observed during Qwen; pre-existing swap and resident workloads were not
controlled. This does not reproduce a tuned reference-Mac result.

A separate qualified [hosted Gemma 26B-A4B MoE attempt](../../tests/bench_records/2026-09-08-requests-gemma-moe-hosted/README.md)
**made applying edits but did not resolve**. It exhausted after 73.707 seconds,
adding reproduction scripts but no production fix; independent acceptance
still fails. All 27 responses completed. The entire hosted study cost
$0.00321032, including one retained preflight registration error. Different
models, routes and budgets prevent a causal comparison with the local trials.

The follow-up September 8 audit checked 98 audience-facing targets in fresh
logged-out browser profiles and verified five linked fragment anchors. The
author link now points to the verified GitHub profile; the pinned Marp PDF
was regenerated and all eight pages visually inspected. Gitleaks 8.30.1 found
no secrets in the dated fetched-history and worktree snapshots. Public issues
are enabled; a signed-in non-collaborator's New issue permission remains
unverified. Exact audit boundaries and PDF hashes are in the
[public-access audit](2026-09-08-public-access.json); the
[earlier readiness record](2026-09-08-readiness.json) remains historical.
The release still needs that independent account check, a reviewed final
commit, and deliberate tag/Release publication.

## Known limits

Completion remains distinct from test acceptance. Live truncated tool arguments
are rejected rather than salvaged. Whole-run cooperative cancellation and
aggregate resource limits remain open; descendants that create separate process
groups can outlive an outer timeout. Local memory, server build, quantization,
context, and reasoning settings materially constrain execution. See
[SECURITY.md](../SECURITY.md), [configuration](../configuration.md), and
[the release tracker](https://github.com/den-run-ai/askme/issues/85).
